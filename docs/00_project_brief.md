# Описание проекта

Проект для курса OTUS "Базы данных": построение отказоустойчивого PostgreSQL-кластера для платформы краткосрочной аренды жилья.

## Цель

Показать связанную систему:

- доменную модель базы данных;
- понятную цепочку миграций;
- отказоустойчивый PostgreSQL-кластер;
- `RPO = 0` (`Recovery Point Objective`, целевая точка восстановления; в проекте - допустимая потеря данных при аварии) для подтвержденных транзакций при отказе основного узла;
- полные резервные копии, архив журнала предзаписи PostgreSQL (WAL) в MinIO и восстановление на выбранный момент времени для защиты от логической порчи данных;
- демонстрационные сценарии для защиты проекта.

## Границы

Проект не реализует полноценное приложение аренды жилья. Клиентский слой представлен демонстрационными подключениями через PgBouncer и HAProxy, а также SQL-сценариями.

Docker-стенд демонстрирует архитектурные принципы. Для локального объектного хранилища, совместимого с S3, используется MinIO, но требования к промышленной системе описываются отдельно: зоны отказа, надежное внешнее объектное хранилище, совместимое с S3, секреты, мониторинг, оповещения и операционные инструкции для действий при отказах и восстановлении.

## Ключевые решения

- Отказоустойчивый контур PostgreSQL строится на Patroni.
- Контур согласования состояния строится на 5 etcd-узлах.
- Запись требует основного узла и минимум 2 синхронные реплики.
- У каждого клиента своя цепочка PgBouncer + HAProxy, чтобы отказ прокси одного клиента не становился общей точкой отказа.
- Миграции применяются через маршрут записи `haproxy-client-a` после поднятия HA-кластера.
- Резервное копирование выполняется отдельным контуром из двух рабочих контейнеров.
- Для демонстрации используется полная резервная копия, архив журнала предзаписи PostgreSQL (WAL) в MinIO и восстановление на выбранный момент времени.
