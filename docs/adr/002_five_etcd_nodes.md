# ADR 002: Пять узлов etcd для согласования состояния кластера

## Статус

Принято.

## Контекст

Patroni нужен надежный источник согласованного состояния: какие PostgreSQL-узлы доступны, кто сейчас имеет право принимать запись и можно ли безопасно выбрать новый основной узел. В проекте эту роль выполняет etcd.

etcd принимает решения через кворум. Это означает, что большинство узлов должно быть доступно для продолжения работы системы согласования. Чем больше узлов в составе etcd-кластера, тем больше отказов он может пережить, но тем выше стоимость демонстрационного стенда.

## Решение

Использовать пять узлов etcd в демонстрационной топологии:

```text
etcd-1
etcd-2
etcd-3
etcd-4
etcd-5
```

Для пяти узлов кворум равен трем. Следовательно, etcd-кластер продолжает работу, пока доступны любые три узла из пяти.

## Обоснование

Топология из пяти узлов выбрана как наглядный учебный вариант. Она показывает правило кворума лучше, чем минимальная схема из трех узлов:

- три узла etcd переживают отказ одного узла;
- пять узлов etcd переживают отказ двух узлов;
- при потере трех узлов кворум теряется, и безопасное согласование состояния становится невозможным.

Такой состав помогает связать теорию кворума с практическим поведением Patroni: PostgreSQL может быть физически запущен, но без согласованного состояния нельзя безопасно назначить новый основной узел.

## Последствия

- Стенд требует больше ресурсов, чем минимальная схема из трех узлов.
- На машине с 6 ядрами и 32 ГБ оперативной памяти топология допустима для демонстрации, но тяжелые сценарии лучше запускать поэтапно.
- Percona Monitoring and Management и сценарии резервного копирования могут увеличивать нагрузку, поэтому их следует демонстрировать отдельно при нехватке ресурсов.
- В документации и демонстрации нужно явно различать отказ PostgreSQL-узла и отказ узла etcd.

## Границы решения

Пять узлов etcd в проекте нужны для демонстрации принципа кворума. В промышленной системе количество и размещение узлов согласования выбирается с учетом зон доступности, сетевых задержек и требований к эксплуатации.
