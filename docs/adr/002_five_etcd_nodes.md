# ADR 002: Пять узлов etcd для согласования состояния кластера

## Статус

Принято.

## Контекст

Patroni нужен надежный источник согласованного состояния: какие PostgreSQL-узлы доступны, кто сейчас имеет право принимать запись и можно ли безопасно выбрать новый основной узел. В проекте эту роль выполняет etcd.

etcd принимает решения через кворум. Это означает, что большинство узлов должно быть доступно для продолжения работы системы согласования. Чем больше узлов в составе etcd-кластера, тем больше отказов он может пережить, но тем выше стоимость демонстрационного стенда.

## Решение

Использовать пять узлов etcd в демонстрационной топологии:

```text
etcd-1
etcd-2
etcd-3
etcd-4
etcd-5
```

Для пяти узлов кворум равен трем. Следовательно, etcd-кластер продолжает работу, пока доступны любые три узла из пяти.

## Обоснование

Кворум - это большинство голосов от исходного состава кластера:

```text
quorum = floor(N / 2) + 1
```

Для трех узлов кворум равен двум. Такой кластер переживает отказ одного узла: если один узел недоступен, два оставшихся все еще могут согласовать решение. Для пяти узлов кворум равен трем. Такой кластер переживает отказ двух узлов: три оставшихся узла все еще образуют большинство.

Два оставшихся узла из пяти не считаются безопасным кворумом, хотя численно это похоже на рабочую пару в трехузловой схеме. Причина в том, что узлы не знают, что именно произошло с остальными участниками. Возможен не полный отказ, а сетевой раздел:

```text
etcd-1 etcd-2 | etcd-3 etcd-4 etcd-5
```

Группа `etcd-3 etcd-4 etcd-5` имеет кворум 3 из 5 и может выбрать leader etcd, принять новое состояние и позволить Patroni безопасно назначить PostgreSQL primary. Группа `etcd-1 etcd-2` физически жива, но не имеет трех голосов, поэтому не может подтвердить новое согласованное состояние. Даже если в этой группе оказался старый leader etcd, он не может продолжать принимать решения без большинства.

Это защищает от split-brain. Чтобы два конфликтующих решения были приняты одновременно, каждое из них должно получить по три голоса. В кластере из пяти узлов любые две группы по три узла обязательно пересекаются хотя бы в одном участнике:

```text
решение A: etcd-1 etcd-2 etcd-3
решение B: etcd-3 etcd-4 etcd-5
```

Общий узел `etcd-3` не проголосует за два конфликтующих решения в одном и том же терме Raft. Поэтому две независимые стороны не могут одновременно получить законный кворум. Если сеть разделилась на `2 + 2 + 1`, кворума нет ни у одной части: система согласования становится недоступной для изменений, но не назначает два primary.

Топология из пяти узлов выбрана как наглядный учебный вариант. Она показывает правило кворума лучше, чем минимальная схема из трех узлов:

- три узла etcd переживают отказ одного узла;
- пять узлов etcd переживают отказ двух узлов;
- при потере трех узлов кворум теряется, и безопасное согласование состояния становится невозможным.

Такой состав помогает связать теорию кворума с практическим поведением Patroni: PostgreSQL может быть физически запущен, но без согласованного состояния нельзя безопасно назначить новый основной узел.

## Последствия

- Система требует больше вычислительных и сетевых ресурсов, чем минимальная схема из трех узлов.
- etcd-кластер сохраняет кворум при отказе двух узлов.
- При потере трех узлов или сетевом разделе без группы из трех узлов согласование новых состояний становится недоступным, но конфликтующее лидерство не подтверждается.
- Мониторинг и эксплуатационные процедуры должны отдельно учитывать отказы PostgreSQL-узлов и потерю кворума etcd.
- Узлы etcd нужно размещать по независимым failure domains, иначе отказ одной зоны может вывести из строя кворум.

## Границы решения

Пять узлов etcd в проекте нужны для демонстрации принципа кворума. В промышленной системе количество и размещение узлов согласования выбирается с учетом зон доступности, сетевых задержек и требований к эксплуатации.
