# RPO и RTO

## RPO

`RPO` (`Recovery Point Objective`, целевая точка восстановления) в проекте читается как допустимая потеря данных при аварии: сколько уже подтвержденных данных система может потерять.

`RPO = 0` означает, что подтвержденные клиенту транзакции не теряются при отказе основного узла.

В проекте это обеспечивается комбинацией:

- `synchronous_commit = on`;
- `synchronous_mode = true`;
- `synchronous_mode_strict = true`;
- `synchronous_node_count = 2`;
- readiness-проверкой write-маршрута HAProxy: primary должен видеть минимум две реплики `sync`;
- DML-guard в прикладной схеме `application`, который отказывает в записи при количестве sync standby меньше двух.

Если доступна только одна синхронная реплика или ни одной, запись должна остановиться. Это защитное поведение, а не деградация гарантии.

## Ограничения RPO = 0

`RPO = 0` не защищает от логических ошибок. Ошибочный `DELETE`, `UPDATE`, `DROP` или плохая миграция будут реплицированы на все узлы.

Для логических ошибок нужно восстановление на выбранный момент времени: восстановление отдельного узла из полной резервной копии и архива журнала предзаписи PostgreSQL (WAL) на момент до ошибки.

## RTO

`RTO` (`Recovery Time Objective`, целевое время восстановления) - время восстановления работы после аварии.

В проекте измеряются три типа RTO:

- автоматическое переключение основного узла;
- восстановление из полной резервной копии;
- восстановление на выбранный момент времени на отдельном восстановительном узле.

## Как измерять автоматическое переключение

```text
1. Зафиксировать время остановки основного узла.
2. Дождаться, пока маршрут записи одного из HAProxy начнет вести на новый основной узел.
3. Проверить `select pg_is_in_recovery()` = false.
4. Выполнить тестовую запись.
5. RTO = время от остановки основного узла до первой успешной записи.
```

## Как измерять восстановление из резервной копии

```text
1. Зафиксировать время старта восстановления.
2. Восстановить отдельный восстановительный узел из полной резервной копии.
3. Запустить PostgreSQL.
4. Выполнить проверочный SELECT.
5. RTO = время от старта восстановления до успешной проверки данных.
```

## Как измерять восстановление на выбранный момент времени

```text
1. Создать точку восстановления или зафиксировать отметку времени до логической ошибки.
2. Выполнить логическую ошибку.
3. Восстановить отдельный восстановительный узел из полной резервной копии и архива журнала предзаписи PostgreSQL (WAL) до нужного момента.
4. Проверить, что данные восстановлены до состояния перед ошибкой.
```
