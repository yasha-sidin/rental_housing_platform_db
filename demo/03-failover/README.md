# 03-failover

Раздел фиксирует проверку автоматического переключения при отказе текущего основного PostgreSQL-узла. Сценарий подтверждает, что Patroni выбирает новый основной узел через согласованное состояние etcd, а HAProxy перестраивает маршрут записи.

## Полученные артефакты

- `artifacts/next_steps.txt` - зафиксированный порядок действий для сценария отказа основного узла.
- состояние кластера до отказа - роли узлов PostgreSQL и состояние маршрутов HAProxy.
- состояние кластера после отказа - новый основной узел и обновленный маршрут записи.
- контрольная запись после переключения - подтверждение, что кластер снова принимает изменения.
- измеренное время восстановления работы - практическая оценка `RTO`, то есть времени восстановления работы после аварии.

## Интерпретация

Артефакты показывают, что отказ одного PostgreSQL-узла не требует ручного назначения нового лидера. Решение о лидерстве принимается Patroni при наличии кворума etcd, а клиентская запись продолжает выполняться через маршрут HAProxy после завершения переключения.
